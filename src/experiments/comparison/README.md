# Новое согласованное сравнение CORnet-RT

Проверяем, насколько один условный checkpoint CORnet-RT сохраняет точность и
устойчивость отдельных моделей при одинаковых профилях аксонального шума в
блоках V1, V2, V4 и IT. В сравнение входят фиксированные специалисты и модели,
для которых профиль выбран последовательным адаптивным поиском.

**Статус.** Оценка на кластере идёт. Каталог `results/comparison_v1` пополняется
по мере завершения прогонов. Опубликованные на этом этапе метрики предварительные.
Старые таблицы из веток `cornet_noises` и `adaptive-sequential-noise` относятся
к предыдущим экспериментам с другими условиями оценки.

## Модели

| Семейство | Что обучается на каждом seed | Число запусков |
|---|---|---:|
| Baseline | CORnet-RT без шума, исходные ImageNet-веса → Caltech | 3 |
| Условная | Один ConditionalCORnetRT на распределении профилей в диапазоне [0, 2.50] | 3 |
| Фиксированная обычная | Отдельный CORnetRT для каждого общего уровня 0.25, 0.50, 0.85, 1.00, 2.50 | 15 |
| Фиксированная с conditioner | Отдельный ConditionalCORnetRT для каждого из тех же уровней | 15 |
| Адаптивная | CORnetRT, рост по блокам; порядки forward, reverse, v2_first | 9 |

Всего 45 обучений, включая baseline. Seed: 42, 43, 44.
Фиксированный специалист с conditioner нужен, чтобы отделить влияние архитектуры
от обучения на распределении профилей.

## Согласование логики обучения

Все варианты используют один датасет, одни train/validation/test split и один
baseline соответствующего seed. Baseline обучается 10 эпох только с новой головой
и 40 эпох целиком. Затем каждая сравниваемая модель получает бюджет 100 эпох,
batch size 32, AdamW (lr=1e-4, weight decay=1e-4), cosine LR на 100 эпох.

Условная модель и оба вида фиксированных специалистов первые 5 эпох работают
без шума. В следующие 25 эпох интенсивность линейно достигает целевого уровня:
у специалиста — его фиксированного профиля, у условной — верхней границы 2.50.
Таким образом, фиксированный профиль 0.50 доходит до 0.50 на 30-й эпохе,
а верхняя граница условной модели в ту же эпоху доходит до 2.50.
Распределение условной модели: 20% нулевых профилей, 30% общих, 30% одно-блочных,
20% независимых. Все выбранные ненулевые значения равномерны от 0 до текущей границы.
Conditioner нормирует профиль на 2.50 и создаёт FiLM scale/shift для блоков сети.

В основном сравнении специалистов и условной модели сохраняются веса последней
эпохи; разные критерии выбора лучшей validation-эпохи не влияют на сравнение.
Validation по-прежнему записывается. Фиксированный conditioner и условная модель
имеют одинаковую архитектуру; обычный специалист соответствует прежней архитектуре.
Шум применяется по расписанию каждой сравниваемой модели. Baseline обучается без шума.

Адаптивный метод после 5 эпох без шума выполняет по 4 эпохи на ступень:
0.10, 0.25, 0.40, 0.55, 0.70, 0.85, 1.00, 1.25, 1.50, 1.75, 2.00, 2.25, 2.50.
Порог: clean validation accuracy не ниже исходного baseline минус 0.10
(именно 10 процентных пунктов). При нарушении порога восстанавливаются последние
принятые веса, состояние оптимизатора и профиль; поиск переходит к следующему блоку.
Transfer PGD на validation записывается, но не управляет принятием ступени.
Не менее 10 последних эпох отведено консолидации; поиск прекращается по бюджету,
даже если не дошёл до всех ступеней. Оставшийся бюджет расходуется на консолидацию.
Если она нарушает clean-порог, выполняется откат. LR следует глобальному счётчику
затраченных эпох, включая отвергнутые. Таким образом, адаптивный метод имеет тот же
бюджет, но собственную логику выбора профиля и отката — это часть исследуемого метода.
Это согласованный по бюджету вариант прежнего поиска, а не точное воспроизведение
его старого обучения до 250 эпох.

## Общая оценка

Один сохранённый checkpoint оценивается при ε=2/255, 4/255 и 8/255.
При смене ε обучения нет. Для всех семейств используется `evaluate_comparison.py`:

- одна и та же случайная подвыборка 512 test-изображений, subset seed 2026;
- точность на чистых изображениях, после прямой white-box PGD и transfer PGD;
- 50 шагов PGD, шаг ε/4, 5 рестартов, выбор кандидата по максимальной потере;
- transfer строится на baseline того же seed с одинаковой случайностью для всех целей;
- два режима: шум выключен и шум включён; во втором MC=3, EOT=16;
- в режиме без шума conditioner всё равно получает заданный профиль: выключить шум
  не означает заменить условие на нулевое;
- для условной модели проверяются общие уровни и zero, а также точные профили,
  найденные адаптивной моделью соответствующего seed и порядка.

Все три метрики считаются на одних и тех же 512 изображениях. Это отличается
от исторических таблиц с full-test clean/transfer. Индексы сохраняются в JSON.
Каждый прогон соответствует одному checkpoint, профилю, режиму шума и ε.
Один `evaluate-all` последовательно выполняет прогоны из манифеста на одной GPU.

| Семейство | Checkpoints | Профилей на checkpoint | Режимов шума | Значений ε | Прогонов |
|---|---:|---:|---:|---:|---:|
| Условная | 3 | 9 | 2 | 3 | 162 |
| Фиксированная обычная | 15 | 1 | 2 | 3 | 90 |
| Фиксированная с conditioner | 15 | 1 | 2 | 3 | 90 |
| Адаптивная | 9 | 1 | 2 | 3 | 54 |
| **Итого** | **42** | | | | **396** |

Девять профилей условной модели включают пять общих уровней, нулевой профиль
и три профиля, найденных адаптивным поиском для того же seed. Три baseline служат
источниками transfer-атак.

## Запуск на сервере

Запускать из каталога с `main.py` и папкой `experiments`, например
`/home/arilmusaev/conditional-noise`. Нужны исходные ImageNet-веса
`weights.pth`, доступный датасет Caltech-256 и Python-окружение из `requirements.txt`.
Веса ImageNet — не Caltech baseline: последний будет обучен заново.

```bash
source "$HOME/venvs/cornet/bin/activate"
python3 experiments/comparison/run.py list
bash experiments/comparison/submit.sh results/comparison_v1 /absolute/path/weights.pth
```

`submit.sh` ставит baseline → обучение → оценку через зависимости afterok.
Перед отправкой заданий он проверяет синтаксис Python и запускает проверки
манифеста, разогрева профиля, переключения шума, совместимости baseline и PGD.
Параллельно выделяется максимум 3 GPU на массив. Окружение можно переопределить
переменной `CORNET_VENV`. Кэш HF задаётся стандартной переменной `HF_HOME`.
Существующие outputs не перезаписываются: для другого протокола нужен новый root.
Время на задачу — 24 часа; при необходимости увеличить `--time` в `sbatch`.

Если обучение уже отправлено, а Slurm отклонил оценочный массив по лимиту задач,
можно запустить оценку одной задачей на одной GPU из каталога с `main.py`:

```bash
sbatch experiments/comparison/run.sh evaluate-all --root results/comparison_v1
```

Отправляй команду после успешного завершения обучения. В этом режиме все конфигурации
считаются последовательно. По истечении лимита времени дождись завершения задания
и повтори ту же команду с теми же параметрами. Скрипт пропустит конфигурации,
для которых уже сохранены CSV и JSON. Текущая незавершённая конфигурация начнётся заново.
Для другого протокола используй отдельный каталог результатов.

Таблицы можно собирать по мере завершения прогонов:

```bash
python3 experiments/comparison/summarize.py results/comparison_v1
```

`results.csv` содержит доступные измерения. `summary.csv` показывает среднее,
стандартное отклонение в процентах и число seed в столбце `seeds`. Группировка
учитывает профиль, ε, режим шума и параметры оценки. Разные адаптивные профили
разных seed остаются отдельными строками.

В промежуточной версии укажи число готовых прогонов из 396 и приложи обе таблицы.
Для парного сравнения сверяй профиль, ε, режим шума, протокол атаки и конкретные
seed по `results.csv`. Истории и аргументы обучения лежат рядом с каждым `model.pt`.
