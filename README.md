# Условный аксональный шум в CORnet-RT

## Статус и задача

В локальном снимке на 19 ноября 2026 года сохранены **387 из 396 прогонов оценки**.
Все сравнения условной и фиксированных моделей на общих уровнях шума завершены
для seed 42, 43, 44 и ε=2/255, 4/255, 8/255. Для адаптивного сравнения пока
отсутствуют девять прогонов seed 44 — reverse с включённым шумом и v2_first
в обоих режимах. Это промежуточный отчёт по фактически доступным результатам.

Проверяем, может ли один условный checkpoint заменить набор отдельно обученных
CORnet-RT при изменении профиля аксонального шума. Основное сопоставление проводится
при одинаковом профиле, ε и режиме инференса.

**Получен настраиваемый checkpoint с измеримой ценой универсальности.**
На общих уровнях 0.25–1.00 условная модель уступает специалистам по точности
на чистых изображениях, но при включённом шуме показывает более высокую accuracy
после текущей white-box PGD. По transfer PGD преимущество зависит от профиля.
Полного сохранения качества специалистов во всех режимах результаты не показывают.

Источники — [все измерения](results/comparison_v1/results.csv),
[агрегированная таблица](results/comparison_v1/summary.csv) и
[отдельные прогоны с метаданными](results/comparison_v1/evaluation).
Подробный протокол и команды находятся в
[README эксперимента](src/experiments/comparison/README.md).

## Модель и обучение

CORnet-RT обрабатывает изображение через блоки V1 → V2 → V4 → IT и классификатор
на 257 классов Caltech-256. В ConditionalCORnetRT добавлен NoiseConditioner.
Профиль `[σV1, σV2, σV4, σIT]` задаёт мультипликативный шум весов свёрток
и поступает в conditioner, который формирует поканальные масштаб и сдвиг признаков.

`all_025` означает `[0.25, 0.25, 0.25, 0.25]`, `all_085` —
`[0.85, 0.85, 0.85, 0.85]`. `zero` — нулевой профиль уже обученной условной сети.
Baseline обучается отдельно без шума и без conditioner.
В режиме `off` случайный шум выключен, но conditioner продолжает получать
заданный профиль. В режиме `on` случайный шум включён.

| Семейство | Варианты | Обучений на трёх seed |
|---|---|---:|
| Baseline | Исходные ImageNet-веса → Caltech, без шума | 3 |
| Условная | Один checkpoint на распределении профилей до 2.50 | 3 |
| Фиксированная обычная | Отдельная модель для общих уровней 0.25, 0.50, 0.85, 1.00, 2.50 | 15 |
| Фиксированная с conditioner | Та же архитектура, что у условной, по одному профилю на модель | 15 |
| Адаптивная | Последовательный рост шума, порядки forward, reverse, v2_first | 9 |
| **Всего** | | **45** |

Baseline обучается 10 эпох только с новой головой и 40 эпох целиком.
Каждая последующая модель начинает с baseline соответствующего seed и получает
бюджет 100 эпох, batch size 32, AdamW с lr=1e-4 и weight decay=1e-4,
cosine learning rate на 100 эпох. Seed — 42, 43, 44.

Фиксированные и условные варианты начинают с пяти эпох без шума. Затем за 25 эпох
интенсивность специалиста достигает его целевого уровня, а верхняя граница
распределения условной модели достигает 2.50. Профиль общий для всего batch.
В условном обучении 20% batch имеют нулевой профиль, 30% — одну общую случайную
интенсивность, 30% — шум в одном блоке, 20% — независимые интенсивности блоков.
Оптимизируются cross-entropy, веса сети и conditioner. Для этих вариантов
оцениваются веса последней эпохи.

Адаптивный метод после пяти эпох без шума повышает интенсивность ступенями
от 0.10 до 2.50, по четыре эпохи на ступень. Ступень принимается, пока clean
validation accuracy не ниже baseline минус **10 процентных пунктов**.
При нарушении порога восстанавливаются последние принятые веса и оптимизатор.
Не менее десяти эпох отведено консолидации с возможным откатом.
Общий бюджет ограничен 100 эпохами, включая отвергнутые ступени.
Из-за этого поиск может закончиться до проверки всех уровней во всех блоках.

## Протокол оценки

Все метрики ниже рассчитаны на одинаковых **512 случайно выбранных test-изображениях**,
с subset seed 2026. Проверена идентичность индексов во всех 387 JSON-файлах.

- White-box PGD строится непосредственно против проверяемой модели с её профилем и режимом шума.
- Transfer PGD строится на baseline того же seed, после чего изображения подаются целевой модели.
- Для каждого ε используется 50 шагов PGD, шаг ε/4 и пять рестартов.
- При ненулевом включённом шуме градиент усредняется по 16 реализациям (EOT), предсказания — по трём реализациям (MC).
- Для детерминированного режима используется по одному вычислению.
- При смене ε используются те же сохранённые веса.

Для оценки используются 42 checkpoint. Пять общих профилей условной модели,
zero и три адаптивных профиля вместе с двумя режимами шума дают 132 конфигурации.
Три ε на конфигурацию дают 396 прогонов. Baseline служит источником transfer-атак.

чем добавление conditioner к фиксированному специалисту.

равен 6.58%, у специалистов около 25–26%. Повышенная остаточная accuracy
специалистов после PGD на этом уровне сопровождается большим падением clean.

## Сила атаки и включение шума

![Точность при разных epsilon для общего профиля 0.85](src/experiments/comparison/figures/epsilon_comparison.png)

При all_085 с включённым шумом у условной модели прямая PGD accuracy падает
с 34.83% при 2/255 до 15.17% при 4/255 и 3.32% при 8/255.
У специалиста с conditioner соответствующие значения равны 32.55%, 11.00% и 1.37%.
Сильная прямая атака по-прежнему существенно разрушает классификацию.

Случайный шум при инференсе меняет результат даже при одном и том же checkpoint.
У условной all_085 его включение снижает clean с 63.61% до 58.33%,
но повышает прямую PGD 4/255 с 4.04% до 15.17%.
У специалиста с conditioner clean меняется с 67.25% до 63.02%,
а прямая PGD 4/255 — с 2.93% до 11.00%.

По transfer PGD 8/255 условная all_085 сохраняет 52.08%, тогда как по прямой
PGD остаётся 3.32%. Такой разрыв показывает ограниченную переносимость атак
с baseline и сохраняющуюся уязвимость к атаке на саму модель.

## Адаптивные профили

На одинаковых найденных профилях сравниваются адаптивный checkpoint и условный
checkpoint того же seed. В таблице шум включён, атака PGD 4/255.
Для reverse и v2_first использованы только общие готовые seed 42 и 43.

![Парное сравнение на найденных адаптивных профилях](src/experiments/comparison/figures/adaptive_matched.png)

Прямой порядок концентрирует сильный шум в V1. Например, у seed 42 и 43
получился профиль [2.50, 0.70, 0.25, 0]. Обратный порядок концентрирует шум в IT.
У v2_first максимальная принятая интенсивность V2 равна 2.25.
Полные профили и решения ступеней сохранены в result.json и adaptive_history.csv.

В доступных парах условная модель уступает адаптивной по clean и превосходит
её по прямой PGD 4/255. По transfer результат зависит от порядка.
Наиболее полное сравнение forward показывает потерю clean на 8.46 п.п.,
выигрыш прямой PGD на 5.73 п.п. и потерю transfer PGD на 5.92 п.п.
Предельные интенсивности всех блоков требуют отдельной интерпретации,
поскольку ограничение в 100 эпох иногда останавливает поиск раньше завершения сетки.

## Вывод и воспроизведение

Один условный checkpoint поддерживает разные профили без повторного обучения.
В общем диапазоне 0.25–1.00 он позволяет выбирать между clean и текущей PGD
accuracy, но уступает отдельно обученным специалистам по clean при тех же условиях.
Диапазон до 2.50 охвачен обучением, однако общий профиль 2.50 даёт резкое падение
точности. Сводные данные подтверждают компромисс между универсальностью,
обычным качеством и устойчивостью, зависящий от профиля.

Оценка использует конечную PGD/EOT-конфигурацию и 512 изображений.
Для reverse и v2_first нужно досчитать указанные seed перед полным сравнением
по трём seed. Старые метрики из предыдущего README получены другим протоколом
и заменены в этом отчёте текущим согласованным сравнением.

На сервере команды выполняются из каталога с main.py и experiments.
Получить таблицы и обновить графики после завершения новых прогонов можно так:

```bash
python3 experiments/comparison/summarize.py results/comparison_v1
python3 experiments/comparison/plot.py results/comparison_v1
```

В этом репозитории код лежит в src. При запуске из корня локального checkout
используйте путь src/experiments/comparison/plot.py.

Локальные 45 файлов model.pt удалены по запросу. В репозитории сохранены метрики,
метаданные прогонов, истории обучения и графики. Checkpoint остаются на сервере.
