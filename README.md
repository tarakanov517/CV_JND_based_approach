# Адаптивный последовательный рост аксонального шума в CORnet-RT

## Цель эксперимента

В эксперименте проверялось, можно ли последовательно увеличивать аксональный шум в блоках CORnet-RT, сохраняя приемлемое качество на чистых изображениях и повышая устойчивость к переносимым атакам. Отдельно исследовалось влияние порядка настройки блоков.

В качестве исходных использовались baseline-модели для трёх случайных инициализаций: 42, 43 и 44. Эксперимент проводился на Caltech-256: 24 791 изображение для обучения, 2 755 для валидации и 3 061 для тестирования.

## Модель и шум

CORnet-RT состоит из последовательных зрительных блоков V1, V2, V4 и IT. Аксональный шум применялся к параметрам свёрток `conv_input` и рекуррентной `conv1` выбранного блока во время обучения. На обычном инференсе стохастический шум отключался: итоговые метрики характеризуют обученные веса, а не случайное зашумление предсказаний.

Интенсивность шума в каждом блоке последовательно проходила уровни 0.25, 0.40, 0.55, 0.70 и 0.85. На каждом уровне выполнялось четыре эпохи. После обработки всех четырёх блоков модель дополнительно обучалась десять эпох для консолидации. Максимальная длина одного запуска составляла 90 эпох.

Рост разрешался, пока валидационная accuracy не падала более чем на 10 процентных пунктов относительно baseline. Для дополнительного наблюдения контролировалась transfer PGD при $\varepsilon=4/255$ на фиксированной части валидации. Эта метрика не заменяла ограничение по clean accuracy.

Проверялись три порядка:

| Профиль | Порядок настройки |
|---|---|
| `forward` | V1 → V2 → V4 → IT |
| `reverse` | IT → V4 → V2 → V1 |
| `v2_first` | V2 → V1 → V4 → IT |

Итого обучено девять моделей: три порядка × три seed.

## Оценка атак

Итоговые модели проверялись на FGSM и PGD при $\varepsilon=2/255$, $4/255$ и $8/255$. Для PGD использовалось 10 шагов и шаг $\alpha=\varepsilon/4$. Оценка выполнялась в двух режимах:

- **white-box** — атака строилась непосредственно на тестируемой модели;
- **baseline-transfer** — атакованные изображения строились на baseline-модели того же seed и переносились на модель с шумом.

## Интерпретация

Лучший общий результат по transfer PGD показал прямой порядок V1 → V2 → V4 → IT. По сравнению с обратным порядком его преимущество наблюдалось на каждом из трёх seed и увеличивалось вместе с силой атаки: в среднем +1.38 п.п. при 2/255, +2.21 п.п. при 4/255 и +3.20 п.п. при 8/255. При этом clean accuracy у этих двух вариантов практически одинакова. Это указывает, что последовательная настройка ранних зрительных блоков перед поздними выгоднее для защиты от переноса атак.

Порядок V2 → V1 → V4 → IT дал немного лучшие средние значения white-box PGD, однако выигрыш относительно `forward` мал, clean accuracy ниже примерно на 0.5 п.п., а разброс между seed больше. Поэтому считать его уверенно лучшим нельзя.

Основное ограничение видно из разрыва между transfer и white-box. Например, у `forward` при PGD 4/255 transfer accuracy равна 59.00%, тогда как white-box accuracy — только 3.46%; при 8/255 это 54.14% против 0.29%. Следовательно, высокий результат transfer в первую очередь означает, что граница решения модели с шумом отличается от границы baseline и атаки плохо переносятся. Это не означает полноценную устойчивость: адаптивная атака, построенная непосредственно на новой модели, почти полностью её разрушает.

Clean accuracy итоговых моделей составляет около 65–66%. Контроллер допустил максимальный уровень во всех блоках, потому что падение не превысило заданный порог в 10 процентных пунктов. Из-за этого текущая сетка закончилась раньше, чем был найден реальный предел допустимого шума.

## Вывод по диапазону до 0.85

Адаптивный последовательный рост аксонального шума повысил устойчивость к атакам, перенесённым с baseline-модели, причём наиболее удачным оказался порядок от ранних блоков к поздним. Результат воспроизводится на трёх seed. Однако эксперимент не подтвердил защиту от white-box атак: при сильной PGD качество осталось близким к нулю.

В первом эксперименте верхний уровень 0.85 был принят во всех блоках. Поэтому был проведён второй эксперимент с расширением диапазона до 2.50.

## Расширенный эксперимент: диапазон от 0.10 до 2.50

Во втором эксперименте проверялись уровни 0.10, 0.25, 0.40, 0.55, 0.70, 0.85, 1.00, 1.25, 1.50, 1.75, 2.00, 2.25 и 2.50. На каждом уровне выполнялись четыре эпохи. После последовательного поиска были предусмотрены 42 эпохи консолидации. Максимальный бюджет составлял 250 эпох, но все модели завершили поиск раньше из-за отклонения уровней, нарушавших ограничение по clean validation accuracy.

Проверялись два порядка на трёх seed:

- `forward`: V1 → V2 → V4 → IT;
- `reverse`: IT → V4 → V2 → V1.

Всего обучено шесть моделей. ### Влияние порядка

Обратный порядок сохраняет в среднем на 2.40 процентного пункта больше clean accuracy. Однако прямой порядок превосходит его по transfer PGD на каждом seed. Средняя разница составляет 17.92 п.п. при $\varepsilon=2/255$, 30.88 п.п. при $\varepsilon=4/255$ и 41.11 п.п. при $\varepsilon=8/255$. Разрыв увеличивается вместе с силой атаки.

Это показывает, что сильный шум в раннем блоке V1 намного эффективнее нарушает переносимость атак с baseline, чем сильный шум в позднем блоке IT. При этом дополнительная transfer-устойчивость достигается ценой снижения clean accuracy.

Расширение диапазона не улучшило ни одну из ключевых метрик. Для `forward` clean accuracy снизилась на 2.69 п.п., transfer PGD — на 3.18–4.12 п.п., а white-box PGD 4/255 — с 3.46% до 0.59%. Для `reverse` clean почти не изменился, но transfer PGD упал на 19.72–42.02 п.п. в зависимости от $\varepsilon$.

## Общий вывод

Эксперимент нашёл границы допустимого роста и показал сильную зависимость результата от порядка блоков. Контроллер, использующий только ограничение по clean accuracy, не находит лучший совместный профиль. Он позволяет первому блоку занять почти весь доступный запас качества, после чего остальные блоки получают минимальный шум.

Лучшим из проверенных вариантов остаётся сбалансированный профиль 0.85 во всех блоках из первого эксперимента. Дальнейшее увеличение интенсивности не усилило transfer-защиту и дополнительно ухудшило white-box устойчивость. Даже лучший расширенный профиль при PGD 4/255 имеет 55.23% transfer accuracy, но только 0.59% white-box accuracy. Следовательно, наблюдаемый эффект остаётся нарушением переносимости атак с baseline, а не защитой от адаптивной атаки на саму модель.

Для следующего поиска уровней контроллеру недостаточно проверять только clean accuracy. Следует ограничить clean-падение и одновременно требовать улучшения целевой adversarial-метрики. Если целью остаётся transfer-защита, можно использовать transfer PGD на отдельной validation-подвыборке. Если нужна настоящая white-box устойчивость, шум необходимо сочетать с adversarial training или учитывать white-box PGD непосредственно при выборе профиля.
